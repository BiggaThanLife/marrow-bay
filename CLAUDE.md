# Marrow Bay (`index.html` + `css/` + `js/`)

Mobile-first Canvas sandbox: a tidal city where NPCs react to the player's background, tags and actions. Vanilla JS, no build step, saves to localStorage `marrowbay_v3`, `migrate()` fills new fields on old saves. Repo `BiggaThanLife/marrow-bay`, Pages from root: https://biggathanlife.github.io/marrow-bay/

## Code layout
`index.html` holds only the page skeleton and an ordered list of `<script src="js/...">` tags. Styles are in `css/style.css`. Scripts are plain (non-module) scripts sharing one global scope, so a top-level `const`/`let`/`function` in any file is visible to every later file and, at call time, to all files. **Load order matters only for code that runs at load time** (e.g. `NPCS.forEach(...)`, `RES.forEach(...)`, `ARCS.x.hook.voices=...`); everything else only runs when called.
- `js/core` helpers · `js/world` tile map, districts, pathfinding, `buildWorld(seed)` · `js/data` pure data tables
- `js/state` the `G` object, clock, tags and attitude · `js/sim` simulation (time, hourly, NPC movement and needs, housing, business, events, crime, rumors)
- `js/systems` city meters, factions, facts, FLACK, arcs engine, council, market, neon, foundry, dockside, seasons, career, companion
- `js/story` HARBOR voice, intro, threads (helpers, data, engine, more), arc data (one file per arc, plus `arc-voices.js`)
- `js/ui` HUD and sheet, popup, quantity picker, phone, bag, build, talk, travel, customize, tutorial, input · `js/menus` building and POI menus (`MENUS[id]`)
- `js/render` palette, tiles, structures, people and vehicles, world draw · `js/save` save and `migrate()` · `js/main.js` tick, frame loop, startup (must stay last)
- To add a file: create it under the right folder (start with `"use strict";`), add its `<script>` tag in `index.html` at the right point in the order.
- **Before every push run `python tools/bump_version.py`** (cache-busting `?v=N` on every file so players never get a mix of old and new files).
- Data tables go in `js/data`, rules in `js/sim` or `js/systems`, drawing only in `js/render`. No gameplay code in `index.html`.

## Testing
Start a server in this folder (`python -m http.server 8765`) and open:
- `/tests/smoke.html`: plays a seeded 30 days, walks NPCs across a schedule change, opens every menu and building, draws every vehicle, saves and migrates an old save, compares with `tests/baseline.json`. Must say "No errors." If behavior changes ON PURPOSE the baseline will differ: check the diff makes sense, then update `tests/baseline.json`. A refactor must leave it untouched.
- `/tests/arcs.html?runs=40`: plays every arc and thread through random and subset strategies and checks the game state after each step. Must say "No errors". The "not reached" list only names endings that need a specific setup (mayor, FLACK-7, mission chain).
- `/tests/sim.html?games=4&days=365`: a year with an idle bot. Flags runaway loops (pinned meters, empty seas, NPC cash exploding or collapsing, starving NPCs, FLACK maxed). Run it after any economy change.
- `/tests/landlord.html`: owns an apartment building for 200 days, clicks every tenant, applicant and problem menu, checks save and migrate. Must say "No errors".
- `/tests/shops.html`: buys every NPC shop, runs 120 days, upgrades and sells, installs every expansion on every business type. Must say "No errors".
- Tests reach every global through `win.eval`, so nothing needs a hook inside the game. The preview browser does not run animation frames, so call `tick(dt)` and `drawWorld(now)` by hand.

## Working rules
- New save fields need defaults in `cityInit()` (called from both `start()` and `migrate()`) or in both places.
- UI copy: sentence case, plain, no jargon. Destructive or costly actions use `ask(title,text,label,fn,back)`. Quantities use `qtyMenu` (live total).
- Menus close with a Close button at the bottom plus the sticky x (`ui(html,btns,isModal,dismiss)`). Major alerts use `popup()` (centered, pauses the game); `alertNews(m,sev)` pops up at severity 3 or more.
- Commit trailer: `Co-Authored-By: Claude <model> <noreply@anthropic.com>` (the model that did the work).
- Thread engine: `THREADS[id]={title,from,hook,start?,beats,endings}`; beats `{wait,ignore,text,choices:[{label,sub,need,fx,next}]}`; `next` and `ignore` may be `'END:key'`. Endings `{name,text,fx,harbor}`.
- Arc engine: `ARCS[id]={title,district,hook?,can,phases:[{name,days,blurb,enter,daily,actions}],resolve,outcomes,status}`. Outcomes set permanent facts (`setFact`), which other systems read with `fact(key)`.

## What exists (story mode, all built)
Endless sandbox. Arc outcomes change the city permanently and play continues after every milestone.
- **HARBOR and FLACK** (the spine). HARBOR is the deadpan city AI; FLACK cameras (a play on Flock) feed it. FLACK coverage 0-100 shows as camera poles on the map, slows heat decay, cuts fence prices, and makes HARBOR redact its own lines. Phone FLACK tab: your file, talk to HARBOR (7 lines), tip, paint a lens, jammers. HARBOR's own arc starts after day 40 once you have heard it all, with five endings (obeys, free, FLACK torn out, merged with the mayor, ghost).
- **Six districts**, each with a faction, a meter and an arc: Greenbelt (Co-op, Harvest, farm buyout), Highline (Trust, Market, share trading and the bubble), the Grid (City Hall, Order, council votes and the mayoral election, which repeats every 60 days and lets you run), Dockside (Union and Harbor Freight, Catch and cargo, fishing gear, manifests, the dock strike), Neon Mile (Vex and the Salt Kings, Underworld, casino with a real house edge, rackets, street race, turf war), Foundry Row (Guild, Output, crafting and jammers, the slag fire).
- **Systems that connect them**: district meters and faction reputation (phone City tab), the permanent fact registry `G.facts`, cross-district effects (Foundry output hurts Greenbelt, FLACK raises Order and lowers Underworld, strikes and crashes move prices), seasons (30 days each, county fair in autumn), career titles, one companion with a perk, home decor, inner voices on arc hooks.
- **Threads** (personal stories, max 2 active, 5 endings each): The Collector (real Vex missions), The Rival, four origin stories, The Picket Line, The Grudge, The Secret, Your Quirk.
- **Arc triggering**: arcs with a `hook` start from a story hook. `G.engage[district]` rises when you enter a building there (+1), work a gig (+2) or own a business (+0.5 a day). Once it reaches `hook.need`, an NPC there offers the arc (accept or "not now", asked again after 4 days). Only one arc runs at a time, with a 6-day gap; a second NPC says they will not talk about it until the first concludes. The mayoral election and HARBOR's arc start on their own. An arc you stay out of ends with a HARBOR digest of what changed.
- **Procedural city**: `buildWorld(seed)` shuffles buildings, lots and parks between the blocks of each district per new game (`G.seed`; seed 0 is the classic layout kept for old saves). Roads, borders, tram stops, the bridge, the plaza and the farm are fixed.

- **Sound and settings**: `js/ui/audio.js` makes small synthesized effects with `sfx(name)` (no audio files; hooked to button taps, menu open, alerts and cash changes) and stores `SET` (mute, volume) in localStorage `marrowbay_settings`. `js/ui/settings.js` is Phone > Settings (also on the title): sound, save, load, export and import a JSON file, full screen and landscape lock, quit to title. Apple browsers have no full screen API, so the full screen buttons open `installHelp()` (Add to Home Screen steps) and iOS Safari also gets a "Full screen on iPhone" button. In landscape (short wide screens) the toolbar moves to a right column, the sheet becomes a side panel and `fitCanvas()` widens `VW`. `manifest.webmanifest` makes a home-screen install full screen. App icon (MB over a night skyline and tide): `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`, `favicon.ico`, drawn by `tools/make_icons.py` (rerun only if the design changes).
- **Landlord system** (apartment buildings, type `rental`): data on the building (`b.tenants`, `b.applicants`, `b.issues`, `b.manager`). Tenants are generated (name, job, background, hidden trait: tidy, noisy, behind, nosy, handy, secretive). Applicants arrive daily and you choose; a property manager (10% of rent) fills flats and pays routine repairs. Problems (leaks, heating, pests, noise, rent overdue, unwelcome visitors) need decisions, tenant mood drives rent, move-outs and district standing. Files: `js/data/tenants.js`, `js/sim/tenants.js` (`rentalDay`), `js/menus/landlord.js`.
- **Expansions and shop buyouts**: each business type has three add-ons in `BT_ADD` (`js/data/expansion.js`); a building has as many slots as its level, add-ons live in `b.add` and apply through `addMod(b,key)` / `addSum` (`js/sim/shops.js`) inside `runBiz`, `bizTraffic` and the landlord sim. NPC shops (`SHOP_DEFS`: market, diner, gull, garage) can be bought from a friendly owner (attitude tier 2+) via a button in their menu. State is `G.shops[poiId]={level,till,paid,last}`; the owner stays on as manager for a wage, `shopsDaily()` pays takings into `till` (collect from the shop or the Biz screen), you get a perk (cheaper seeds, meals, fuel, free rounds), monthly tax, and you can expand to level 3 or sell back at 70%. Menus: `js/menus/expansion.js`.
- **Walking tenants**: `js/sim/walkers.js`. Up to 10 tenants of your apartment buildings appear as people on the map (`WALKERS`, rebuilt from tenant lists, never saved): out of the door by day, to places in their district, home by night. Tap one to talk (`tenantMenu`). Driven by `walkersHourly()` and `tickWalkers(dt)`.
- **NPC looks**: named NPCs use `NPC_LOOK` (`js/data/npc-looks.js`: skin, hair, style, dress, beard, hat) and tenants get a stable look from `tenantLook(t)`; both draw through `drawNpc` in `js/render/people.js`. Keep the cast mixed in skin tone and gender when adding people. Reyes and Ines are women, Vex is a man (text pronouns match).
- **Charts and alerts**: `js/ui/charts.js` has `lineChart(values,opts)` (inline SVG), `pushHist`, `sumHist`, `issueTotal()`. History is saved on each building (`b.hist`, 30 days of profit), each owned shop (`s.hist`) and the market (`G.mkt.hist[shareId]`, `G.mkt.pf` portfolio, 60 days). Charts show in the building menu, shop menu, Biz overview, trading desk and share menu. Tenant problems show as red badges: buttons take a `badge:n` field (`ui()` draws it), the Biz toolbar button shows the total, and the map draws a red number over an apartment building with problems.

## Design rules to keep
- Connect the systems instead of widening them: district state, NPC goals, world effects, visible feedback.
- Every district meter should influence at least two other systems, and 0 or 100 is never simply good.
- Three kinds of state: resources (fluctuate), conditions (temporary events and `councilMod`s), facts (permanent).
- No ECS and no build step. Prefer data tables over `if(type===...)` chains.
- Do not add path caches, indexes or A* until population actually grows.

- **Clinic, barber and tailor shops**: `SHOP_DEFS` gained `clinic` (Dr. Bell), `barber` (Kofi Mensah, new NPC, Highline) and `tailor` (Priya Nair, new NPC, Grid). Perks: free treatment and +55 energy, free haircuts and dye, clothes and hats 25% cheaper. The new NPCs have entries in `js/data/npcs.js`, `npc-looks.js`, `WAGE` and `OWNER`; `cityInit()` creates `G.npcs` state for any NPC an old save lacks. `OPEN_TO_ALL` in `places.js` keeps the barber and tailor open even to people their owner distrusts, as before. Shops test now buys all seven shops and opens each shop menu.
- **Hints instead of a long tutorial**: the HARBOR onboarding (`js/ui/tutorial.js`) is now 3 cards (getting around, toolbar, the rest is up to you). The rest of the old cards became one-time hints in `js/ui/hints.js` (`HINTS`: people, hungry, money, bills, heat, biz, tenants), each shown as a popup the first time its condition is true. `hintsCheck()` runs at the top of `hourly()`, shows at most one, never stacks on an open popup, and waits until onboarding is finished. Shown hints are saved in `G.tips`; a save with no `G.tips` is treated as having seen them all (set in `migrate()` before `cityInit()`). Players can switch hints off in Settings (`SET.hints`). To add a hint, add an entry to `HINTS` and a trigger to `tests/hints.html`.
- **HARBOR introduction**: the intro (`js/story/intro.js`) now has a "What I do" screen (step 2) after the player's background and before their accommodation: HARBOR keeps the city's records, the poles on the street corners are FLACK cameras, it is "also listening". It stays vague on purpose so the "What HARBOR Is" arc still reveals something. A one-time hint, `cameras` in `js/ui/hints.js`, fires the first time the player is within 6 tiles of a working camera and points to the Phone's FLACK tab.
- **Crowding fixes**: the street lattice is one tile wide (roads every 5 tiles, 4x4 blocks), so someone is nearly always next to whatever you tap. In `js/ui/input.js` a tap on a tram stop or a placed structure only goes to a person standing almost on that spot (reach .5 tiles, otherwise 1.1, was 1.3); `walkerAt(fx,fy,reach)` takes the same reach. FLACK cameras are still placed by `FLACK_SITES` at junction centres (so coverage and `camNear` are unchanged) but `drawCam` draws the pole in the corner of the junction, against the nearest building corner, head turned to the crossing. Widening the streets was considered and not done: saved building keys, structures and positions are all tile coordinates, so it needs a full coordinate remap and save migration.
- **Shady business types**: `BT` gained `pies` (meat pie shop), `cages` (micro-cage hostel) and `wellness` (wellness centre), reached through "Change business type". They run through the ordinary retail branch of `runBiz`. `shady:{rep,inspect,fine,news}` costs the district standing every day and gives a daily chance of an inspector fine (paid from the till, then cash); `calm:{heat}` lowers the player's heat each day. Pies sell cheap and earn about double a café per sale, the hostel has huge demand but loses the most standing, and the wellness centre earns little and keeps heat down. Expansions are not defined for them (`expansionButton` returns nothing when `BT_ADD` has no entry). Covered by `tests/darkhumor.html`. Not built from the brainstorm list: Grübr, Mortuary Board, and the heavier schemes (insurance fraud, organ ordinance, astroturfed gentrification).
- **GPS sky view and Googull**: Phone > GPS (`js/menus/gps.js`) opens `#gpsmap`, a full-screen overlay showing the whole city from above (`gvBase()` draws roofs, roads and ground onto an offscreen canvas, pins come from `gpsList()` which now carries `id` and `kind`). Drag to pan, pinch, wheel or +/- to zoom, Fit shows the whole city, tap a pin for a card with Auto-walk, Show route (dotted route drawn on the map), Googull it and Favorite; List opens the old list (`gpsMenu`). Googull is the city's parody search page (`googullPage(d)`): a knowledge panel with rating, open/closed status from `OPEN` and `isOpen`, the owner's attitude to you, "People also ask" and three reviews. Text lives in `js/data/googull.js`, one entry per place kind (`GG`, plus `stop`, `mine`, `lot`); add an entry whenever a new kind of building is added. Rating is the entry's `base` nudged by a hash of the place. Test: `tests/gps.html`.
- **Business names and their Googull pages**: every building you own gets a name from `BIZ_NAMES[type]` (`js/data/biz-names.js`) the first time `bizName(b)` is called, saved on the building as `b.name` with `b.nameFor` (the type it was picked for); changing the business type picks a new name, and names stay unique across your buildings. Stalls are named by `stallName(s)`, a hash of their position, and nothing is saved for them. The GPS map shows these names, the building menu says "Known as ...", and the Googull page for them is built live by `ggMine(b)` in `js/menus/gps.js`: rating from district standing, last day's profit, staff, tenant mood and open problems; tagline from `BIZ_TAGS`; reviews from `BIZ_REV`, with a real current problem (an open tenant issue, no staff) reviewed by name. Add names to `BIZ_NAMES` when adding a business type. Covered by `tests/gps.html`.
- **Chains and managers**: owning two or more of the same business type (`CHAIN_TYPES`: cafe, bar, workshop, pies, cages, wellness) gives each location `chainMod` through `addMod`: +5% foot traffic and -4% supply cost per extra location, up to four extras (so +20% and -16%). An inspector's fine at one location calls `startScandal(b)`: the other locations of that type lose 1 standing in their district and 15% of their foot traffic for 5 days (`G.scandal[type]` holds the end day; it fades by itself). Any business except apartments and homes can have a manager (`b.mgr`, a button in the building menu): 10% of takings goes to wages, the till is banked into cash each night, an empty place hires the best-value person from `G.pool`, farms sell crops automatically, and theft and fines are halved. Apartments keep their own property manager (`b.manager`). New titles in `CAREERS`: Chain Owner (three of one type) and Regional Boss (a business in every district). The Biz overview now lists buildings by name and marks managed ones. Test: `tests/chain.html`.
- **Crime: dirty money, the police file and prison**: data in `js/data/law.js`, rules in `js/sim/law.js`, menus in `js/menus/prison.js`. (1) **Dirty cash** (`G.dirty`, `earnDirty()`): Vex jobs (courier, collect, heist), fenced goods, fenced cars and racket pay go to a separate pool that shops, bills and the bank cannot use. It is washed through any building you own except farms and homes: `launder(b,amt)` cleans up to `washCap(b)` a day for a fee (`washFee`: 15% bars, pie shops and wellness centres, 25% others, +10% with a manager). Managers launder automatically each night, and the pawn shop's Cash exchange swaps dirty for clean at 60 cents so nobody is stuck. (2) **Police file** (`G.notor` 0-100, `lawTier()` 0-3, `LAW_TIERS`): rises each hour by half your heat, fades 1.2 a day while heat is zero, plus more from laundering and arrests. Watched (25): fences pay less. Wanted list (50): bank refuses loans and the trading desk, and `lawDaily()` may raid one of your businesses (fine, shut two days via `b.shut`, a quarter of dirty cash seized). Public enemy (75): `LAW_LOCKED` places (bank, Estate, club, estate agent) refuse you in `openPOI`. City Hall, clinic, food, work and home never lock. (3) **Prison**: a new Foundry Row building (`SPEC` '9,4', kind `prison`). `bust()` is a short detention below tier 1 and heat 4, otherwise `goToJail(sentenceDays())`: fine, half of dirty cash seized, hot goods and stolen cars lost, `G.jail={start,until,days,work,appeal}`. While jailed `tick()` freezes, the map ignores taps, Go and Build are blocked, and `worldPanel()` shows `jailMenu()` (sit out time, laundry work that shortens the sentence every third shift, yard, lawyer, guard bribe). Businesses keep running through `advance()`, so managers matter. Saved in `G.jail`, restored on load. (4) **Records office** at City Hall (`recordsMenu`): community service, fixer, clerk bribe, informing on Vex's crew, each lowering the file. Test: `tests/crime.html`. Not built: casino laundering, crew members, rival crews, multi-step heists.
- **Game speed and courier time**: `TIME_RATE` (`js/core/util.js`) is how many game minutes pass per real second while you play. It was 6 (a day took four minutes) and is now 4 (six minutes). `tick()` and every walking or driving estimate (GPS card, GPS list detail) use it, so change it in one place. Hunger, energy, prices and income are per game minute or day, so everything takes proportionally longer in real time. Courier runs get `courierMinutes(j)`: the walk from where you stand to the pickup plus the delivery, on foot, times 1.5, plus 20 minutes (before, it ignored the walk to the pickup). Vex's other jobs keep their old game-minute deadlines. The smoke baseline's `ticks.t`, `m_phone` and `m_town` moved because of this.
- **Action scenes and the tap shield**: `js/data/scenes.js` lists which buttons play a short pixel scene before acting (`SCENE_RULES`: label pattern, type, kit, caption; `SCENE_MS` gives each type's length). `js/ui/scenes.js` draws them on a 96x48 canvas (`SCENE_DRAW`: `work` with kits crate, pan, rake, spanner and forge; `cash`; `rest` with bed and clinic) inside `#actscene` (not `#scene`, which is the map canvas). `ui()` now sends every button through `runButton(b,e)`: a matching button plays its scene, then runs its own `fn` exactly once; taps on buttons while a scene plays are ignored; a tap after `SCENE_SKIP_AFTER` (400 ms) skips. To animate a new action, add a rule; to add a type, add a drawing to `SCENE_DRAW` and a length to `SCENE_MS`. `shield(ms)` raises a clear full-screen `#shield` after every menu opens (250 ms), closes (300 ms) and after a scene ends (450 ms) so double taps and ghost clicks cannot hit what is underneath. `SET.scenes` (Settings: Action scenes, off by default for reduced-motion devices) switches scenes off. A game running inside a frame skips scenes unless `SCENE_FORCE` is set, so the other test pages stay fast. Planned but not yet drawn: purchase, eat and drink, nature, gamble, sneaky, travel, paper, build and social scenes. Test: `tests/scenes.html` (it clears the saved settings when done, because the settings menu saves `SET`).
